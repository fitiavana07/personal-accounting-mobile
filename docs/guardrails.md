# Guardrails

Rules that used to be only prose in `CLAUDE.md` and are now enforced by tools.
This page lists each one, where it lives, what you see when it blocks something,
and how to get unblocked. Start with **"I'm blocked by..."** if something refuses
to work.

## Setup on a fresh clone

- `git config core.hooksPath .githooks` enables the git `commit-msg` hook
  (`core.hooksPath` is local git config, so it is not carried by the clone).
- `jq` must be installed (the Claude Code hooks use it). `bash` too.
- The Claude Code settings and hooks (`.claude/`) are committed and apply to
  everyone who opens the project in Claude Code.

## Overview

| Rule | Mechanism | Where |
|------|-----------|-------|
| Claude must not read `local.properties` (signing secrets) | `permissions.deny` + PreToolUse hook | `.claude/settings.json`, `.claude/hooks/block-local-properties.sh` |
| Claude must not run `make` or `scripts/release.sh` | `permissions.deny` | `.claude/settings.json` |
| No instrumented / device tests | `permissions.deny` (commands and the `androidTest` dir) | `.claude/settings.json` |
| No `Co-Authored-By` in commits | `attribution.commit = ""` + git `commit-msg` hook | `.claude/settings.json`, `.githooks/commit-msg` |
| Conventional Commits | git `commit-msg` hook | `.githooks/commit-msg` |
| Git hooks cannot be bypassed by Claude | PreToolUse hook | `.claude/hooks/block-no-verify.sh` |
| Version bumped only by the release script | PreToolUse hook | `.claude/hooks/guard-build-files.sh` |
| Dependencies only via the version catalog | PreToolUse hook | `.claude/hooks/guard-build-files.sh` |
| Build and unit tests pass before Claude finishes a turn | Stop hook | `.claude/hooks/check-build-and-tests.sh` |
| Layering: `features/` has no UI deps, UI never touches DAOs, only ViewModels (and their factories) use repositories, DAOs never use repositories | Unit test | `app/src/test/.../ArchitectureTest.kt` |
| No deprecated APIs | Kotlin `allWarningsAsErrors` | `app/build.gradle.kts` (`kotlin { compilerOptions }`) |
| No obsolete `SDK_INT` checks (minSdk 19), no deprecated resources | Lint checks `ObsoleteSdkInt` and `Deprecated` as errors | `app/build.gradle.kts` (`android { lint }`) |

Exit code **2** from a Claude Code hook blocks the tool call and shows the hook's
stderr to Claude. Exit code **1** from a git hook aborts the commit.

## Details

### `local.properties` is unreadable for Claude

`Read(./local.properties)` is denied, and `block-local-properties.sh` refuses any
`Read`, `Grep` or `Bash` call whose path or command mentions `local.properties`.
The file holds the release keystore passwords. Gradle, `release.sh` and your own
shell still read it normally. Limit: the Bash check is text matching (`cat
loc*.properties` would slip through). A real guarantee needs the Claude Code
sandbox with a filesystem deny.

### `make` and `scripts/release.sh`

Denied rules: `Bash(make)`, `Bash(make *)`, `Bash(*scripts/release.sh*)`. The
Makefile and the release script are for you only. Limit: a wrapper such as
`bash -c "make test"` is not matched by the pattern.

### Instrumented tests

Denied: `Bash(*connected*AndroidTest*)` and `Edit(app/src/androidTest/**)` (the
`Edit` rule covers `Write` too). Tests run on the JVM with Robolectric.

### Commits: `.githooks/commit-msg`

- The first non-comment line must match
  `<type>(<scope>)!: <description>` with `type` in `feat fix docs style refactor
  test chore perf build ci revert`. `Merge ...`, `Revert "..."`, `fixup! ...`,
  `squash! ...` and `amend! ...` generated by git are accepted.
- Any `Co-Authored-By:` trailer (case-insensitive) is rejected.
- `attribution.commit = ""` in `.claude/settings.json` stops Claude Code from
  adding its own trailer in the first place.

The hook applies to you and to Claude. `block-no-verify.sh` additionally blocks
Claude from `git commit --no-verify` / `-n` (also combined flags like `-anm`) and
from touching `core.hooksPath`. You can still use `--no-verify` yourself.

### Version bumps: `guard-build-files.sh`

Blocks an `Edit` of a `*build.gradle.kts` whose text mentions `versionCode =` or
`versionName =`, and a `Write` that changes either value. `versionNameSuffix` is
not affected. `scripts/release.sh` edits the file with `sed`, outside Claude Code,
so it keeps working (it also commits `chore: bump version to ...` and tags).

### Version catalog: `guard-build-files.sh`

Blocks an `Edit`/`Write` to any `*.gradle.kts` that declares a dependency with a
string literal, such as `implementation("group:name:1.0")` or
`implementation(platform("..."))`. Declare it in `gradle/libs.versions.toml` and
use `libs.*`.

### Build and tests before finishing: `check-build-and-tests.sh`

A `Stop` hook. When Claude is about to end its turn and something under
`app/src`, `app/build.gradle.kts`, `gradle/libs.versions.toml`,
`build.gradle.kts` or `settings.gradle.kts` is newer than the last successful
check, it runs `./gradlew assembleDebug testDebugUnitTest`.

- Success: records `.claude/.last-successful-check` (gitignored) and lets Claude
  finish. A turn that changed nothing relevant costs nothing.
- Failure: exits 2 so Claude keeps working, with the last 40 lines of output. If
  Claude already tried once that turn (`stop_hook_active`), the turn is allowed to
  end so it cannot loop forever.
- Timeout: 600 seconds, set in `settings.json`.

### Architecture test: `ArchitectureTest`

Reads the imports of every file under `app/src/main/java` and fails on:

- a file in `features/` importing `...accounting.ui`, `ViewModel`/`viewModelScope`/
  `lifecycle.viewmodel`, `androidx.fragment`, `androidx.navigation`,
  `android.view`, `android.widget` or `android.app.Activity`
  (exemption: `features/sync/ForegroundTracker.kt`, an Application lifecycle
  callback that only counts started activities);
- a `*Dao.kt` in `features/` importing a `*Repository`;
- a file in `ui/` importing a `*Dao`;
- a file in `ui/` importing a `*Repository` unless its name ends with
  `ViewModel.kt` or `ViewModelFactory.kt` (factories receive the repositories).

It is import-based, so it does not see fully qualified names written inline or
what a function does. The rules are also tested with synthetic bad sources.

### No real network in unit tests: `NoRealNetworkInTestsTest`

Robolectric tests run under `TestAccountingApplication`
(`app/src/test/resources/robolectric.properties`), which sets
`AppContainer.httpClientFactory` to a client that throws before connecting. Every
fetcher built by `AppContainer` (P2P, CEX, CoinGecko, Yahoo) shares that client,
so opening the Home screen or Cex prices screen in a test can no longer reach
p2p.binance.com or an exchange. A test that needs responses builds its own
fetcher around a fake instead. A new fetcher added to `AppContainer` must take
the shared `httpClient`, or `NoRealNetworkInTestsTest` should be extended to cover it.

### Compiler and Lint

- `kotlin { compilerOptions { allWarningsAsErrors.set(true) } }`: any warning,
  including a deprecated API, fails the build (`warnings found and -Werror
  specified`). Replace the API, or suppress with a justified `@Suppress`.
- `lint { error += setOf("ObsoleteSdkInt", "Deprecated") }`: run
  `./gradlew lintDebug`. Lint is not part of the Stop hook, and it currently
  reports two unrelated `AppCompatResource` errors (menu `showAsAction`).

## "I'm blocked by..."

| Message mentions | Cause | What to do |
|------------------|-------|------------|
| `local.properties` | Read guard | Intended. Give Claude the value yourself if it is really needed (never the passwords). |
| `Permission ... has been denied` for `make` / `release.sh` / `connected...AndroidTest` | `permissions.deny` | Run it yourself in your own terminal. |
| `Commit rejected: the subject must follow Conventional Commits` | `commit-msg` hook | Fix the subject: `type(scope): description`. |
| `no Co-Authored-By trailer allowed` | `commit-msg` hook | Remove the trailer. |
| `git commit --no-verify skips the commit-msg hook` / `core.hooksPath must stay` | `block-no-verify.sh` | Fix the commit message; run the git command yourself if you really need to bypass. |
| `versionCode/versionName are bumped only by scripts/release.sh` | `guard-build-files.sh` | Run the release yourself, or edit the version in your editor. |
| `declare the library in gradle/libs.versions.toml` | `guard-build-files.sh` | Add it to the catalog and use `libs.*`. |
| `assembleDebug testDebugUnitTest failed` at the end of a turn | Stop hook | Real build/test failure; Claude is meant to fix it. |
| `warnings found and -Werror specified` | `allWarningsAsErrors` | Fix the warning shown above that line. |
| `... must not depend on the UI` / `only a ViewModel ... may use a repository` ... | `ArchitectureTest` | Move the code or the import to the right layer. Do not edit the test to make it pass. |

### Turning a guardrail off (you, not Claude)

- Claude Code hooks: `/hooks` in a session, or remove the entry from
  `.claude/settings.json`. `permissions.deny` rules live in the same file.
- Git hook: `git commit --no-verify` once, or `git config --unset core.hooksPath`.
- Stop hook only: delete `.claude/.last-successful-check` to force a run, or
  remove the `Stop` entry to disable it.

## Tests of the guardrails

`app/src/test/.../tooling/CommitMsgHookTest.kt` and `ClaudeHooksTest.kt` run the
scripts with sample input (`ClaudeHooksTest` is skipped when `jq` is missing).
`ArchitectureTest.kt` covers the layering rules. They all run with
`./gradlew testDebugUnitTest`. The Stop hook script and the deny rules themselves
are not covered by tests.

## Not enforced (still only in `CLAUDE.md`)

TDD order, writing a manual testing checklist, UI style, integer money amounts,
UUID ids, a test for every DAO query, a migration for every entity change, writes
to synced tables going through `ChangeTracker.inTransaction`.
